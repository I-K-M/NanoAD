# N08a — NanoRAM strict resource admission

Status: experimental implementation slice. Parent: [N08](../../tickets/001-nanoad/N08-resource-admission.md), [NAN-001](../../specs/001-nanoad.md), [NAN-002](../../specs/002-resource-research.md).

## Resource contract

NanoRAM consumes a consistent, freshly reconciled host/lab snapshot. Its pure governor separates physical memory, system commit, configured guest RAM, per-workload overhead, shared provider/controller peak, startup extras, retained disk growth and temporary disk. Every value is in checked bytes. The initial strict policy includes overhead in the lab memory cap, independently for physical and commit (the two are not added). Defaults are a 3 GiB lab memory limit, at least 2 GiB host physical reserve, 512 MiB commit reserve, 24 GB installed and operation-peak disk caps, 512 MiB host disk reserve and a two-second observation age (configurable up to five seconds). These are provisional design policy, not measured safe Windows allocations.

For each guest, configured RAM is conservatively charged to both physical and commit; no overcommit, swap, ballooning or pagefile-growth credit. Shared peak is charged once and must cover concurrently outstanding operations. A pending start or stopping workload retains its full peak envelope. An active workload must have independently verified readiness and a qualified steady upper bound. Do not reduce an envelope from a momentary idle measurement. All outstanding disk growth is included and temporary reservations are summed; current installed bytes, retained-after, temporary peak and caller-available space are checked separately through NanoDisk. Active startup scratch must be absent or already included in the inventory. There is no credit for hoped-for reclamation.

Host available RAM already reflects current usage. To avoid double-charging where evidence permits, a verified active workload may supply a unique lower bound already charged to the same host sample/revision. Physical credit must be proven non-reclaimable; commit credit must be independently attributed to system commit. Credits are bounded by the workload envelope and host consumed totals. RSS, configured guest RAM, process private commit in isolation or estimated release are not sufficient evidence. No automatic credit is inferred; zero credit is deliberately conservative and may refuse an otherwise feasible start. Shared overhead has no credit in this slice.

## Native host observations

Windows x86-64 uses K32GetPerformanceInfo to collect system-wide committed pages, current commit limit, physical available pages and physical total; checked conversion uses the returned page size. Commit headroom is not inferred from the preliminary doctor's process-specific ullAvailPageFile. K32GetProcessMemoryInfo observes working set, peak working set, private commit and peak commit from a caller-supplied verified live process handle. It cannot discover or prove provider ownership, distinguish shared guest memory perfectly, attribute all kernel costs, or qualify an upper bound. GetDiskFreeSpaceExW queries caller-available bytes on a verified local lab-volume path, not a hard-coded drive. Samples use GetTickCount64, no extra threads or daemon. Linux admission is deliberately unsupported; existing doctor output remains informational.

A real reconciler must verify the host execution scope (including VM/job/container restrictions as applicable), provider inventory, attachment states and the disk volume identity. A host-wide sample is not sufficient to establish that scope. Provider process discovery, attribution, peak calibration and complete physical allocation inventory remain real-host work. Unknown or estimate-only costs fail strict admission. The host can still change after observation; this is conservative admission, not an OS-enforced reservation or absolute guarantee.

## In-memory reservations

The fixed ledger holds up to 32 distinct workload UUIDs. Preview is pure; reserve re-evaluates under a future caller-owned exclusive lock, adds a pending reservation and advances revision only on success. A simultaneous plan using the old revision is rejected; recalculation includes all outstanding starts and scratch. Immediately before launching a pending workload, recheck a fresh reconciled snapshot including that reservation. Host RAM, commit or disk drift can refuse launch without dropping the reservation. There is no release API here; a future trusted reconciliation after confirmed stop or cleanup must establish released resources, preserve outstanding reservations and update the inventory under N09's durable lock/journal. Revision is session-local, not a crash-safe generation. No mutation command, automatic module stop, real hypervisor start, or approval-plan bypass is introduced.

All samples must be from the same host boot and clock domain. The caller binds revision and scope to the observations; no snapshot, credit or upper bound is accepted directly from an untrusted user manifest. N11/N12 will provide consented deactivation choices and re-plan after observed release.

## Validation and limitations

Run the pinned toolchain: `zig fmt --check build.zig src`, `zig build test`, `zig build -Doptimize=ReleaseSafe`. Tests cover exact arithmetic and overflow, unknown and estimated costs, stale/future timestamps, missing scope, physical and commit refusal, pending reservations and competing starts, stale revision, prelaunch host drift, credits, retained/scratch/free-space separation, and native Windows observations of the CI host/current process. Synthetic measurements are not a real provider overhead benchmark.

N08 remains open until actual VirtualBox overhead is measured and qualified, a real fresh reconciler and N09 lock/journal are integrated, and admission is exercised on a disposable lab. Independent review is outstanding. No VM, host policy or persistent data was modified. Rollback: revert scoped commits. Test imports and trace updates are explicit supporting changes to the ticket boundary.
